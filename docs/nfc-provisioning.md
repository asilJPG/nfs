# Прошивка NFC-меток

Метки — **NTAG 424 DNA** (NT4H2421Gx). Обычные NTAG213/215/216 не подходят: они
хранят статичную ссылку, её можно скопировать и ставить себе штампы дома.

## Что нужно

- NTAG 424 DNA (наклейки или карты), 1–2 на точку;
- Android-телефон с NFC;
- приложение **NXP TagXplorer** или **NXP TagWriter** (бесплатные);
- доступ к `NFC_MASTER_KEY` продакшена.

## 1. Получить ключи метки

UID чипа виден в любом NFC-ридере (например, NXP TagInfo) — 7 байт, 14 hex-символов.

```bash
npm run mock-tag -- --uid 04A1B2C3D4E580 --counter 1 --keys
```

Выведет:

- **K_meta** (SDM Meta Read key) — одинаковый для всех меток;
- **K_mac** (SDM File Read key) — уникальный для этого UID;
- пример готовой ссылки для проверки.

> K_meta общий, потому что UID лежит внутри зашифрованных данных: расшифровать их
> ключом, выведенным из UID, невозможно. K_mac уникален, поэтому утечка ключа одной
> метки не даёт подделывать остальные.

## 2. Записать URL и включить SDM

В NDEF записывается ссылка:

```
https://app.<ваш-домен>/t?picc_data=00000000000000000000000000000000&cmac=0000000000000000
```

Нули — это плейсхолдеры, чип перезаписывает их сам при каждом касании.

В настройках SDM (Secure Dynamic Messaging) включить:

| Параметр | Значение |
|---|---|
| SDM Enabled | да |
| UID Mirror | да |
| SDM Read Counter Mirror | да |
| PICCData Offset | позиция после `picc_data=` |
| SDMMACInputOffset | равен SDMMACOffset (сообщение для MAC пустое) |
| SDMMACOffset | позиция после `cmac=` |
| SDM Meta Read Access | ключ, в который записан **K_meta** |
| SDM File Read Access | ключ, в который записан **K_mac** |
| SDM Counter Retrieval | ограничить или оставить открытым — на нашу проверку не влияет |

Записать ключи в соответствующие слоты (обычно AppKey 1 → K_meta, AppKey 2 → K_mac),
затем **сменить AppKey 0** на собственный ключ, иначе метку сможет перепрошить кто угодно.

## 3. Проверить

Приложить телефон. Должно открыться:

```
https://app.<домен>/t?picc_data=<32 hex>&cmac=<16 hex>
```

и произойти редирект в Telegram. Если видите «Не удалось прочитать метку» — не сходится
ключ или смещения мирроров. Если «Метка не зарегистрирована» — крипто в порядке,
осталось завести UID.

## 4. Завести UID в системе

`/admin` → «Регистрация метки»: UID, кофейня, подпись. Либо SQL:

```sql
select public.admin_register_tag('04A1B2C3D4E580', '<tenant-uuid>', null, 'у кассы');
```

После этого кофейня в своём кабинете привязывает метку к точке.

## Что делать при утере метки

`/dashboard/tags` → «Отключить». Ссылка перестаёт работать мгновенно; счётчик и
ключи не меняются, так что метку можно вернуть в строй, если она найдётся.

## Ротация мастер-ключа

`NFC_MASTER_KEY` ломает **все** метки при смене — из него выводятся и K_meta, и все
K_mac. Хранить в менеджере секретов, бэкапить отдельно от базы. Плановая ротация
означает перепрошивку всего парка, поэтому в `nfc_tags.key_version` заложена версия
ключа: при необходимости можно вести две версии параллельно.
