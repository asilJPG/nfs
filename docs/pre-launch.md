## Чем проверять

```
npm run verify    # selftest + sql + flow + brand + contrast
npm run build
```

- `verify:sql` — 19 миграций и 28 проверок логики на pglite, без внешних сервисов.
- `verify:brand` — оформление кофейни доезжает до карточек гостя и текст на них читается.
- `verify:contrast` — обходит отрендеренный лендинг и валит сборку на тексте ниже WCAG AA.

### Чего проверки не ловят

- **Контраст только на лендинге.** `/apply` и `/login` тянут server actions и через
  них supabase-клиент, которому нужны переменные окружения. Экраны за авторизацией
  не покрыты вовсе.
- **Переносимость цвета.** `verify:contrast` считает цвета, но не то, во что они
  компилируются. Классы вида `text-white/40` превращаются в `oklab()`, который
  понимают не все браузеры — где не понимают, подпись остаётся без цвета.
  Приглушённый текст задавать токенами `--color-ink-*` / `--color-carbon-*`,
  а не модификатором прозрачности. Проверка: в собранном CSS не должно быть
  `color:oklab(`.
- **Живые данные.** Все проверки работают на пустой или синтетической базе.
